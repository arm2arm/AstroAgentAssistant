# P103 — SH21 vs SH26 parameter comparison, inner box, SHBOOST split

Added 2026-08-23. Module `src/sh26/plots/p103_sh21_vs_sh26_inner_box.py`.

## What it is

Full-catalog (402M v220826) comparison of SH21 vs SH26 for the 5 stellar
parameters, split by SHBOOST. Layout: 5 rows × 3 panels.

- Rows: Distance [kpc], AV [mag], Teff [K], logg [dex], [M/H].
- Col (a): SH21 vs SH26 hexbin (SH21 x, SH26 y) + 1:1 line, both SHBOOST
  subsets overlaid in distinct colours (True = `#c2185b` pink, xgbdist used;
  False = `#1976d2` blue).
- Col (b): Δ = SH26 − SH21 distribution (step histogram, p1–p99 window, both
  subsets overlaid, red dashed Δ=0).
- Col (c): mean Δ vs dist50, binned ±1σ (both subsets), red dotted Δ=0.

Numbers are per-subset: n, median Δ, MAD, fraction negative — written to the
JSON sidecar `per_quantity`.

## Selection — the "inner box" ambiguity (IMPORTANT)

There are TWO different boxes in this project; the user calls both "the
inner box". Confirm which before running:

| Box | X (kpc) | Y (kpc) | converged count (v220826) |
|---|---|---|---|
| P85–P93 "inner box" (default) | [-4,4] | [-3,3] | ~16.4M (16,355,280 finite l,b,d) |
| P103 box ("~27M") | [-5,5] | [-4,4] | ~27.5M (26,369,290 in P103 after finite-13-q) |

The user said "27M in the inner box" → that is **X[-5,5] × Y[-4,4]**, NOT the
P85–P93 X[-4,4]×Y[-3,3]. A quick count-probe on Newton (pyarrow read of
l,b,dist50,MISSING only) settles it in ~30 s before committing to a full run.

Box is on XGal/YGal (derived, `dataio._add_derived(df,["XGal","YGal"])`,
RSUN_KPC=8.19), converged-only (`MISSING==False`), finite in all 13 input
quantities.

## Full-402M render path (pyarrow-direct, ~3.5 min)

Same pattern as P101/P102. Deploy fresh `src/` to Newton, run a
`/tmp/run_p103_direct_v220826.py` that:
1. `pyarrow.dataset(DATA).to_table(columns=[14 cols])` (read ~15 s),
2. `to_pandas()` (~20 GB), `dataio._add_derived(df,["XGal","YGal"])`,
3. `df = df[df["MISSING"]==False]`,
4. `PlotContext(outdir=/lustre/<user>/tmp/sh26_p103_full_v220826, ...)` + `make()`.

Outputs PNG+PDF+JSON to `/lustre/<user>/tmp/sh26_p103_full_v220826/`.
Verified: 26,369,290 stars, SHBOOST True 16,710,392 / False 9,658,898.

## Appending to sh26_all_figures.pdf

`sh26_all_figures.pdf` is the canonical full-plot bundle (102 pp as of
2026-08-23 pre-P103: 89×50M + P82/P90-93/P99/P100/P101/P102). To append a new
full-catalog figure, do NOT re-run `combine_figures.py` (it only merges
`paper/figures/*.pdf`, which holds the 50M campaign, not the full-catalog
renders). Instead append the rendered PDF page directly with PyMuPDF:

```python
import fitz  # or import pymupdf as fitz (fitz API deprecated in recent builds)
base = fitz.open('sh26_all_figures.pdf')
new  = fitz.open('/lustre/<user>/tmp/.../sh26_p103_....pdf')
base.insert_pdf(new)
base.save('/tmp/out.pdf')          # MUST save to a DIFFERENT path
base.close()
```

**PITFALL (hit 2026-08-23): `base.save(same_path)` raises
`ValueError: save to original must be incremental`.** Save to a temp path,
then `mv` over the original. Verify with `pdfinfo` page count + `pdftotext -f N`
on the new page. Commit + push.

## Deploy pitfall (git archive --skip-old-files)

When re-deploying changed `src/` after a code fix, do NOT use
`tar --skip-old-files` — it keeps the STALE files on Newton (the render then
runs old code). `rm -rf /tmp/sh26_p103_src && mkdir && tar -xf -` every time,
and `grep` the deployed file for the expected change (e.g. box bounds /
`top=0.94`) to confirm before launching.

## Label-collision fix (multi-panel figures)

`ctx.save()` appends ` · N = ...` + `(P##)` to EVERY panel title and stamps a
red P## tag top-left of every non-colorbar axis. With a 5×3 grid the default
`subplots_adjust(top=0.96)` let the figure suptitle collide with row-1 panel
titles (verified by vision: overlap + truncation). Fix: `top=0.94`,
`hspace=0.35`, single-line panel titles at fontsize 10 (no `\n` in titles —
two-line titles push row-1 up into the suptitle).
