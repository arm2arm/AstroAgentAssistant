## Isolated-render deploy pattern (do NOT touch the user's live checkout)

`/lustre/<user>/hermes/SH26` is the user's **live working copy with uncommitted
changes** (39 modified files observed this session). NEVER `git pull`/`checkout`/
`stash`/edit it there — `git pull` fails on the dirty tree and worse, it would
clobber in-flight notebook work. Render from an isolated copy instead:

1. Agent host: `git push` the commit you want, then
   `tar czf /tmp/sh26_code_<sha>.tgz --exclude=__pycache__ --exclude=.git
   src scripts pyproject.toml requirements.txt`
   (repo = `/home/hermes/projects/SH26`).
2. Stream to Newton and extract to an ISOLATED dir on the shared mount:
   `ssh arm2arm@141.33.4.144 "cat > /tmp/x.tgz" < /tmp/x.tgz` then on Newton
   `tar xzf` into `/lustre/<user>/tmp/<job>/`. Write the sha into `<dir>/.head`
   so the render log records provenance.
3. **`/lustre/<user>` IS shared between Newton (141.33.4.144) and <compute-node>.nnew**
   — marker-file test verified both directions this session. Code + figures
   written on either side are readable on the other; no Newton→<compute-node> scp needed
   for the arm2arm tree. (The old "separate mounts / md5-verify at destination"
   guidance is about staleness of already-page-cached files under memory
   pressure, NOT the arm2arm tree.) <compute-node> reads the catalog and this code
   straight off `/lustre/<user>/...`.
4. **Verify the deploy imports before the heavy render** (cheap, catches a bad
   tar/short clone): on <compute-node>,
   `python -c "import sys; sys.path.insert(0,'<dir>/src'); from sh26.registry
   import registry; print(len(registry.all_ids()), 99 in registry.all_ids(),
   100 in registry.all_ids())"` and confirm the new raw column is in the schema.

## Multi-plot union-read render recipe (`scripts/render_p99_p100_full.py`)

Several plots sharing a dataset: read the **union of their pushed columns once**,
apply `MISSING==False` once, `_derive` the derived set once, then call each
`registry.make_fn(NN)(pdf[keep].copy(), ctx)`. For P99+P100 the union was just
5 columns (`MISSING, SH_OUTFLAG, ruwe, l, b`) — `SH_OUTFLAG` read raw (it's a
real column in v220826), `ruwe2` derived from `ruwe,l,b`. Build the union set
explicitly (do NOT `_resolve` the SH_OUTFLAG deps — those 15 input cols are no
longer needed once the flag is stored).

**Timings (402M, <compute-node>):** read 5 cols 44 s → converged 402,121,784 →
327,477,457 in 18 s → P99 make 310 s → P100 make 53 s (the 327M-row
`query_RUWE(crowding=False)` chunked-SkyCoord loop is ~7M rows/s, NOT the slow
path) → total 571 s, peak ~15 GB, 531 GB free. No Dask (the CLI OOMs at 402M via
repartitiontofewer). One process renders both — cheaper than two separate reads.

## Nested-ssh launch (no inline nohup/heredoc/&)

Inline `nohup ... &` and heredocs over the double-hop `ssh Newton → ssh <compute-node>`
hang on channel teardown or trip the Hermes shell parser ("& backgrounding"
block). Pattern that worked:
- Stream a launcher `/tmp/render_*.sh` + a status `/tmp/render_status.sh` from
  the host.
- Launch: `ssh arm2arm@141.33.4.144 "ssh <compute-node>.nnew 'nohup bash /tmp/render_*.sh
  > /tmp/render_*.nohup 2>&1 </dev/null & echo LAUNCHED'"`.
- The launcher runs the python render, writes a clean log (strip
  WARNING/INFO/distributed), and drops `RENDER_RC=` + a `_DONE` marker.
- Poll with `render_status.sh` (ps + log tail + figure ls + free -g). Keep each
  `sleep` under the ~420 s foreground cap (use `sleep 540` then a separate
  short `ssh -o ConnectTimeout=10` status call; a `sleep 900` in one foreground
  call is rejected — max 600 s).

## QA note for large figures

`vision_analyze` is flaky at full resolution — repeated timeouts on the 4598-px
P99 full-res PNG. What worked: crop the multi-panel figure into rows (PIL:
top/bottom halves) and/or downscale to ~640px, then vision each crop; the
single-panel P100 analyzed fine at 640px and the P99 top+bottom crops came back
clean on retry. Keep the **text-based QA (n_points + non-white fraction) as the
primary gate** — it's deterministic and always available; vision is a spot-check
only.
